- `live/engine.rs`: CPA-authored create-only staging, bounded journal parsing, locking, private recovery-directory validation, pre-begin orphan cleanup, and recovery experiment.
- `live/backup.rs`: CPA-authored Linux synthetic-root encrypted rollback-material foundation using the [`ring` 0.17.14 AEAD API](https://docs.rs/ring/0.17.14/ring/aead/index.html); format version 3 binds the exact replacement transaction ID, recovery-key provider kind/version and opaque-reference digest together with private Linux owner/group/mode metadata. Restart loading has no public raw-key bypass: it validates durable state and binding before opening only the caller-supplied provider reference, then reopens the current root-to-artifact namespace chain and requires every root/directory/file identity to match the held objects before decrypting. It maps every non-available result to a blocker without create/delete fallback. Synthetic tests verify exact arguments and call counts, including zero opens for missing, malformed, binding/identity-conflicting or ciphertext-digest-mismatched state detectable before key access; a post-validation rename/replace race or AEAD authentication failure instead blocks after one open. The raw opaque reference and key are not persisted, public receipts omit content digests, backup artifacts are revalidated as owner-private single-link objects, and the module still does not publish or replace client files. Windows and macOS remain explicitly unsupported.
- `live/linux_replacement.rs`: CPA-authored Linux synthetic-root, single-existing-leaf replacement and rollback slice based on the public [`openat(2)`](https://man7.org/linux/man-pages/man2/openat.2.html), [`renameat2(2)`](https://man7.org/linux/man-pages/man2/renameat2.2.html), [`flock(2)`](https://man7.org/linux/man-pages/man2/flock.2.html), [`fallocate(2)`](https://man7.org/linux/man-pages/man2/fallocate.2.html), [`posix_fallocate(3)`](https://man7.org/linux/man-pages/man3/posix_fallocate.3.html), [`fstatat(2)`](https://man7.org/linux/man-pages/man2/stat.2.html), and [`fsync(2)`](https://man7.org/linux/man-pages/man2/fsync.2.html) contracts. It introduces no third-party code or dependency. Complete journal capacity plus fixed per-event pending slots and rollback storage are physically allocated before `CommitPrepared`; exact torn tails are repaired without shrinking reserved extents. A durable key-create intent is gated on an explicit transaction-idempotent provider capability. A synthetic-root shared lock serializes real overlapping transactions. Descriptor-relative `RENAME_EXCHANGE` preserves the displaced entry for live or restart verification and bounded undo; raw no-follow device/inode/type metadata permits restoration of a window-raced symlink, public-mode file or hard-linked entry without accepting it as valid configuration. Rollback uses a durable stage intent, a rewriteable preallocated inode, original private read-only modes and no-replace publication. Encrypted pre-images are reopened through the existing provider boundary, and exact target/stage identities make post-exchange/pre-event restart recovery idempotent. Production cannot construct its synthetic-root approval; multi-target operation, native tool validation/locking, cleanup, Linux production key custody and all real client writes remain unavailable.
- `live/linux_secret_service.rs`: CPA-authored Linux-only Secret Service recovery-key provider boundary for isolated synthetic sessions. Stable case-sensitive non-secret lookup attributes bind application, purpose, format, transaction, effective UID and a random item identifier; the opaque reference and checksummed secret envelope independently bind the same identity. A caller-approved owner-private directory supplies a descriptor-relative `flock` reconciliation lock, and only tests can construct that approval. Create always uses `replace=false`, reconciles an already published item by transaction attributes, refuses duplicates, and never calls Unlock or Prompt. Open and delete locate by attributes instead of persisted object path and distinguish missing, locked/prompt-required, wrong-identity, corrupt and unavailable states without creating or overwriting. Contract tests use an in-memory fake service and injected search/create/get/delete faults; they do not touch a real keyring. The D-Bus transport uses the Secret Service `plain` session under the accepted same-login-account threat model; a fixed isolated native keyring fixture and encrypted session negotiation remain production gates. The module is not connected to `apply_configuration` or any real client write.
- `live/cleanup_journal.rs`: CPA-authored Linux synthetic-root durable cleanup-phase journal. It publishes five immutable, owner-private, bounded phase records with descriptor-relative no-follow opens, a directory lock covering namespace enumeration, capacity/duplicate or prefix validation and no-replace publication, file/directory/root flushes, exact transaction/root/provider-reference binding, and restart reconstruction of the provider-agnostic cleanup sequence. Every event also persists one expected transaction-workspace leaf plus device/inode identity; its workspace phase requires the exact non-serializable receipt from `live/workspace_removal.rs`, and restart/key deletion revalidate that retained proof. After a durable `Complete`, it can non-mutatingly revalidate the exact inactive completion proof and issue an opaque prerequisite for a future artifact-retirement protocol. This slice deliberately has no production constructor for the initial trusted workspace-target evidence, so cleanup-journal creation remains fail-closed until the durable replacement transaction supplies that binding. It does not yet unlink or garbage-collect completed records, implement an operating-system key provider, or enable real client writes.
- `live/workspace_removal.rs`: CPA-authored Linux synthetic-root removal proof for one exact empty owner-private transaction workspace. It holds the existing transaction lock, requires the path leaf and opened device/inode to match the opaque target carried by durable cleanup state, binds root/transaction-directory/workspace identities and the cleanup transaction/provider reference, flushes a private pending proof before descriptor-relative exact directory removal, flushes the transaction directory and root, and publishes an immutable `.removed.json` proof only afterward. Restart revalidates the proof and workspace-name absence before key deletion; pending, missing, cross-workspace, renamed, replaced, non-empty or mismatched state fails closed. It deliberately retains proofs and does not remove transaction contents, issue initial trusted workspace-target evidence, implement a recovery-key provider, authenticate against a hostile same-user process, or enable real client writes. Hostile same-account resistance is an explicit first-release threat-model non-goal; this does not relax cross-account isolation, accidental-concurrency checks or any remaining live-write gate.
- `live/completion_tombstone.rs`: CPA-authored Linux synthetic-root completion-tombstone persistence, bounded restart enumeration, and exact authorized logical removal after the cleanup gate confirms key deletion. Removal renames the exact active record through a flushed `.deleting` intent to a bounded inactive `.removed` proof; fresh exact authorization can resume either durable state, and the store exclusively constructs a receipt after the inactive proof plus namespace/root are flushed. A separate non-mutating verifier accepts only a `Complete`-phase proof authorization and reconstructs that exact receipt from the inactive proof; active or deleting state is refused. The stable directory descriptor and compatible shared/exclusive advisory lock now cover enumeration, duplicate/capacity validation, publication, logical removal and proof verification, with deterministic concurrency tests for the 64-entry boundary and duplicate-publish/removal serialization. The retained proof is deliberately not garbage-collected in this slice. The module uses descriptor-relative no-follow opens, exact owner-private modes, private staging plus no-replace atomic publication, restart durability repair, file/directory/root flushes, and transaction/root/provider-reference binding; it implements no operating-system key provider, general durable cleanup journal, workspace removal, proof garbage collection, or real client write.
- `live/recovery_key.rs`: CPA-authored recovery-key provider interface, fail-closed open-outcome mapping, and provider-agnostic terminal-cleanup ordering gate. It contains no provider implementation itself.
- `live/macos_keychain.rs`: CPA-authored fail-closed macOS Keychain boundary plus a pure in-memory `SecItem` contract harness. The production constructor deliberately returns unavailable on macOS until the binary has a fixed signing identity and a dedicated access-group entitlement that can be verified before any query. Contract tests fix Data Protection Keychain selection, non-synchronizing generic-password attributes, `WhenUnlockedThisDeviceOnly`, no-interaction authentication context, persistent-reference read-back, transaction/current-user/access-group commitments, duplicate-add recovery, exact-reference deletion and conservative status mapping. They do not call Security.framework or claim native restart, lock, cross-user or durability evidence. No file-Keychain, disk, environment, CLI, database or network fallback exists, and the module is not connected to real configuration writes.
- `live/windows_dpapi.rs`: CPA-authored Windows-only synthetic-root recovery-key provider. It uses current-user DPAPI with UI forbidden and transaction-bound optional entropy, a bounded self-checking plaintext envelope, a transaction/blob-digest reference, owner-only protected DACLs, retained no-delete directory handles and exclusive cross-instance locking. Creation writes and flushes an owner-private `.pending` blob, then calls the documented user-mode `NtSetInformationFile(FileRenameInformation)` path on that file handle with `RootDirectory` null, a fixed simple final leaf and replacement disabled; this is the source-handle current-directory rename form rather than an absolute-path move. It verifies that the final object retains the staged 64-bit volume serial plus complete 128-bit `FILE_ID_INFO` identity, the stage name is absent, the final object remains owner-private and non-reparse, and the reopened flush handle still names the retained store directory before flushing and reading the final value back. `GetFileInformationByHandleEx(FileIdInfo)` failure or an all-zero unsupported 128-bit ID fails closed without a fallback to ReFS-unsafe `BY_HANDLE_FILE_INFORMATION`. An exact create retry removes only a private bounded unpublished stage when no final exists, or authenticates an already published value and revalidates plus flushes the retained store directory before returning it; repeated flush failure remains unavailable instead of being reported as success. Simultaneous final/stage state remains fail-closed and preserved. Tests cover complete 128-bit comparison including a synthetic upper-half ReFS collision, missing-ID refusal, distinct live-object identities, same-path object replacement, every create boundary, same-provider post-publish retry with persistent flush failure, no-overwrite conflict preservation, restart reopen and authenticated idempotent deletion. DPAPI plaintext buffers and temporary key arrays are zeroized. Linux/macOS fail with `UnsupportedPlatform` before namespace creation, and there is no environment-variable, command-line, database, network or plaintext-file fallback. It is not connected to the Tauri apply command or any real configuration write.

## Public protocol sources

- Windows security-descriptor ownership and access-token APIs: Microsoft Learn documentation for [`SetNamedSecurityInfoW`](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setnamedsecurityinfow), [`GetSecurityDescriptorOwner`](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-getsecuritydescriptorowner), [`OpenProcessToken`](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-openprocesstoken), and [`GetTokenInformation`](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-gettokeninformation) (accessed 2026-10-15). Creation sets the owner to the current process-token user SID; recovery compares the file owner with that SID in addition to verifying the protected owner-rights DACL.
- macOS extended ACL enumeration: Apple `acl_get_fd_np(3)` and `acl_get_entry(3)` manual pages (accessed 2026-10-15). The private-directory boundary queries the already-open object, rejects any extended ACL entry rather than relying only on BSD owner/mode metadata, and separately confirms that a lock path still names the locked inode.
- Windows recovery-key source: Microsoft [`CryptProtectData`](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) and [`CryptUnprotectData`](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptunprotectdata) (accessed 2026-10-15). The synthetic provider uses current-user protection, explicitly omits `CRYPTPROTECT_LOCAL_MACHINE`, sets `CRYPTPROTECT_UI_FORBIDDEN`, supplies the same transaction-bound optional entropy in both directions, frees DPAPI output with `LocalFree`, clears plaintext output before freeing it, and adds an application-level envelope and blob digest because the documented tamper error is not stable.
- Windows staged publication source: Microsoft [`NtSetInformationFile`](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntsetinformationfile), [`FILE_RENAME_INFORMATION`](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information), and the public [`FileRenameInformation`](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/3668ae46-1df5-4656-b481-763877428bcb) contract (accessed 2026-10-15). Microsoft explicitly directs user-mode callers to use the `NtSetInformationFile` name and documents `DELETE` access plus a simple leaf with null `RootDirectory` as a source-directory rename. The provider sets `ReplaceIfExists` false; the public protocol requires failure when the destination already exists. Unsupported filesystem/API behavior returns unavailable and leaves evidence rather than falling back to the Win32 wrapper's absolute-path form or copy/delete publication.
- Windows stable-identity source: Microsoft [`BY_HANDLE_FILE_INFORMATION`](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information), [`GetFileInformationByHandleEx`](https://learn.microsoft.com/en-us/windows/desktop/api/winbase/nf-winbase-getfileinformationbyhandleex), and [`FILE_ID_INFO`](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info) (accessed 2026-10-15). Microsoft states that the legacy 64-bit file index is not guaranteed unique on ReFS and directs callers to `FileIdInfo` for the 128-bit identifier; `FILE_ID_INFO` documents comparison of that full ID together with the 64-bit volume serial. The synthetic provider therefore has no legacy identity fallback and rejects unsupported or all-zero 128-bit IDs.
- macOS recovery-key planning sources: Apple [Using the keychain to manage user secrets](https://developer.apple.com/documentation/security/using-the-keychain-to-manage-user-secrets), [TN3137: On Mac keychains](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains), [`kSecAttrSynchronizable`](https://developer.apple.com/documentation/security/ksecattrsynchronizable), [Restricting keychain item accessibility](https://developer.apple.com/documentation/security/restricting-keychain-item-accessibility), [Sharing access to keychain items](https://developer.apple.com/documentation/security/sharing-access-to-keychain-items-among-a-collection-of-apps), [`SecTaskCopyValueForEntitlement`](https://developer.apple.com/documentation/security/sectaskcopyvalueforentitlement(_:_:_:)), [`kSecReturnPersistentRef`](https://developer.apple.com/documentation/security/ksecreturnpersistentref), [Updating and deleting keychain items](https://developer.apple.com/documentation/security/updating-and-deleting-keychain-items), and [Security Framework result codes](https://developer.apple.com/documentation/security/security-framework-result-codes) (accessed 2026-10-15). The pure contract records the intended Data Protection Keychain request and conservative outcome mapping, while native implementation remains blocked on a fixed signed access-group identity and isolated VM/user lifecycle evidence.
- Linux desktop recovery-key sources: freedesktop.org Secret Service [collections and items](https://specifications.freedesktop.org/secret-service/latest/ch03.html), [lookup attributes](https://specifications.freedesktop.org/secret-service/latest/lookup-attributes.html), [service methods](https://specifications.freedesktop.org/secret-service/latest/org.freedesktop.Secret.Service.html), [collection `CreateItem`](https://specifications.freedesktop.org/secret-service/latest/org.freedesktop.Secret.Collection.html), [item methods](https://specifications.freedesktop.org/secret-service/latest/org.freedesktop.Secret.Item.html), [`plain` transfer session](https://specifications.freedesktop.org/secret-service/latest/ch07s02.html), [locking and unlocking](https://specifications.freedesktop.org/secret-service/latest/unlocking.html), [prompts](https://specifications.freedesktop.org/secret-service/latest/prompts.html), and [standard errors](https://specifications.freedesktop.org/secret-service/latest/errors.html) (accessed 2026-10-16).
