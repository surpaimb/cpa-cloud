# ID-05 / BILL-03 员工套餐目录跨能力文案真值补充契约

状态：2026-10-03 合同先行、开发预览；本文初稿形成时尚未实施。现已完成 Web 实施并开立 Draft PR，新增 test-only 服务端回归仍待第三次只读审阅；不声称新 HEAD 的 CI 或 G 验收已经通过。精确起点是 `main` 的 `85dec421b994fdd8b9b95d2a019aa9f92a490a16`。本批只校正员工自助只读套餐目录的一句说明文案，并以有意义的能力组合测试防止再次误导。

## 依据、历史事实与覆盖范围

原[员工自助套餐目录契约](employee-self-plan-catalog-contract.md)的“Browser and acceptance boundary”要求文案同时说明目录值不是权益或持久报价，且“purchase/cancellation/renewal still requires an administrator”。这是该契约写成时的事实，不应把它倒述为当时的错误。之后，[本人订阅取消](employee-self-subscription-cancel-contract.md)、[本人月度续购](employee-self-monthly-renewal-contract.md)和[本人 one-time 套餐购买](employee-self-plan-purchase-contract.md)分别引入独立、默认关闭且有各自前置条件、授权和服务端资格校验的入口；它们并非目录开关的隐含能力。[本人订阅状态](employee-self-subscription-status-contract.md)、[本人钱包余额](employee-self-wallet-balance-contract.md)与[员工自助基础](employee-self-service-foundation-contract.md)仍各有自己的门控。

本文**仅取代原目录契约中“购买、取消与续购仍须管理员操作”这一句静态文案要求**。原目录的只读请求、币种/分页/游标、当前启用套餐及 revision、商业执行关闭时不可用、身份/Origin/会话、错误与数据最小化、无自动读取、晚响应清理、桌面/390px 等要求继续有效；上述各独立操作合同也不被本文修改。[开发预览接口契约](preview-contract.md)的目录及续购路径仍按原定义，不新增或重释 API。目录显示的现价不能充当购买报价；看到目录也不能推断本人具有购买、取消或续购资格。

## 当前误导与期望说明

当前 `web/src/SelfApp.tsx` 的 `SelfPlanCatalogPanel` 在“当前可用套餐目录”下写着“仅展示查询时该币种已启用套餐的当前信息，不是权益或持久报价；购买、取消与续购仍须管理员操作。”该面板在 `employee_self_plan_catalog=true` 且 `employee_self_plan_purchase!==true` 时显示。因取消与月度续购不以目录或 one-time 购买开关为前置，以下实际可出现的组合会把已获独立授权的本人操作误说成只能找管理员：

| 会话能力组合 | 只读目录与本人操作的真值 |
| --- | --- |
| 仅目录开启，购买/取消/续购关闭 | 目录可按需读取；不能从目录发起三种操作。 |
| 目录 + 本人订阅状态 + 本人取消，购买关闭 | 目录仍只读；合格的本人有效订阅可通过独立取消入口处理，不由目录赋权。 |
| 目录 + 本人订阅状态 + 本人钱包余额 + 本人月度续购，购买关闭 | 目录仍只读；仅合格的本人已到期月订阅可走独立续购报价/确认，不是任意新购。 |
| 目录 + 钱包余额 + one-time 购买均开启 | 现有购买面板取代只读目录面板；购买仍经独立报价、当前密码与服务端事务校验。 |

实施时该句宜改为：

> 仅展示查询时该币种已启用套餐的当前信息，不是权益或持久报价。此目录只读，不会在这里购买、取消或续购；本人能否执行这些操作，以各自独立授权入口及服务端资格校验为准。

等价文案必须同时保留“当前观察值而非权益/持久报价”“目录本身不执行三种操作”“每种本人操作依独立授权和服务端资格”三层含义。不能再无条件声称都须管理员，也不能暗示打开目录、看到套餐或某个价格即授予购买权、保证可取消/续购或承诺支付、模型权益。商业执行关闭、目录为空、页面切换时的既有提示和清空行为保持原义。

## 实施及验收边界

除下述唯一 test-only 服务端回归外，预期代码变更仅限该 UI 单句及 `web/src/test/SelfApp.test.tsx` 中针对实际能力组合的测试。不得改 API、flag、注册/认证、密码、CSRF、Origin、DDL、账本/财务、购买/取消/续购事务、CSS 或依赖。默认关闭时无目录控件/请求；目录开启也只能由员工明确输入币种并点击读取，不在挂载或登录时自动拉取。结果/游标仍仅留组件内存；币种、账号/会话变化、退出、卸载、失败和迟到响应的清理规则不回退。购买能力为真且前置能力齐备时继续由现有购买面板取代只读目录面板，而不是同时显示两套入口。

根任务完成本文的只读审阅并明确放行后，再做本地实施与独立测试。测试不能只把旧字符串断言替换成新字符串：至少覆盖上表前三种只读目录组合、目录关闭及购买面板替代组合；断言中立说明出现的位置、旧绝对表述消失、购买关闭时没有购买控件/报价或购买调用、取消和续购只出现在各自资格候选的独立订阅入口。保持并运行既有显式读取、可用/不可用/空目录、游标、错误清空、账号或会话切换、登出和迟到响应测试；不能通过放宽这些断言让文案测试通过。模拟会话能力不代替服务端资格验证，应分别报告 UI 门控证据和既有服务端合同的边界。
