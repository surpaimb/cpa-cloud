# 员工直接使用 CC Switch

状态：CPA Cloud 已实现开发预览的 Chat Completions API Key 闭环；CC Switch 与实际工具的完整兼容性仍待验证。

## 接入流程

1. 管理员配置上游账号、模型与员工权限，生成默认不过期的员工 Key。
2. 管理员向员工交付服务地址、员工 Key 和该工具适用的模型/配置说明。
3. 员工在 CC Switch 中配置 CPA Cloud 为供应商，为自己使用的工具启用配置。
4. 工具携带 CPA Cloud 员工 Key 调用服务端；不需要专用员工端、微信或员工网页账号。

CC Switch 是配置工具，也有可选本地代理模式。普通配置模式下由 AI 工具直接请求 CPA Cloud；
不能把 CC Switch 画成所有请求必经的网络代理。服务端不依赖它的后台进程或专有心跳。

## 服务端职责

- 一个员工 Key 可用于该员工获授权的工具和模型；每个工具的协议、路径与模型名需分别配置。
- 使用正常受信任的 HTTPS，不能要求所有员工先安装专用软件才能建立 TLS 信任。
- 所有权限、撤销与用量归属在服务端执行，不依靠 CC Switch 隐藏模型或保护权限。
- 更新上游账号及刷新会员凭据不要求员工更新 Key。地址或客户端配置变化另行通知。
- CC Switch 不识别自定义的接入材料封装是正常的；默认交付标准地址和原始员工 Key。
- 不承诺 CC Switch 与我们的旧员工端具有相同的系统安全存储能力；第三方客户端存储由其实现负责。

## 配置指引

规划中的后台接入说明将按 Codex、Claude Code、Gemini CLI 分开，列出 Base URL、认证方式、模型和已验证版本；当前未实现这些工具需要的全部协议或一键配置。
上游有 Gemini 账号不等于 Gemini CLI 已兼容；需单独验证其客户端协议，不能只以 /v1/models 通过代替。
仅将已验证的客户端配置标记为可用，提供普通手工配置路径，不强制 CC Switch。

第一版不必修改、打包或 fork CC Switch。后续可评估配置导入协议；优先不在 URL 中携带长期 Key，
不把一次性显示的秘密存入共享链接、网页日志或统计。当前没有实现一键导入按钮。

## 验收

- 使用未经修改的 CC Switch 配置 CPA Cloud，分别验证实际工具的请求、SSE、多轮工具调用及取消。
- 同一个员工 Key 跨已支持工具可用；无额外设备登记、客户端心跳或 Gate 调用。
- 正常服务重启、升级和上游凭据刷新后，已有 Key 仍可认证。
- 撤销、员工停用和模型权限更新对第三方客户端同样生效。
- 每次测试记录 CC Switch、AI 工具、服务端版本及具体配置；不把文档支持当作实测结论。
