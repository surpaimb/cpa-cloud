基线 `1a969e6`，2026-09-24。沿用 [差距审计](sub2api-gap-audit-2026-09-24.md)、[功能矩阵](feature-parity-plan.md)和 AGENTS.md。本地总协调任务负责契约、代码审查、冲突解决及独立验收；实现使用侧栏可见的 GPT-5.6 Sol 项目任务和独立工作树，禁止在协调任务内部再生成隐藏协作子任务。

这三项是本轮可验收增量，不删除通用预算、会员、商业和其他总目标。不得读取真实数据目录/凭据，不操作本机已有服务；测试用临时目录、随机端口、合成凭据。只轻量 CI，不创建 tag 或安装包。

## A：账号与模型路由管理

交付后端、网页与测试，按当前 app/service 模式集成，保留已存在的四协议、Codex 生命周期、治理/预算与池调度。

- 模型增加正整数 `revision` 和 `archived` 视图。`PATCH /admin/api/v1/models/{id}` 接收 `expected_revision` 和可选 `upstream_id`、`upstream_model`、`enabled`；ID 不可改名。列表默认隐藏归档项，`include_archived=true` 可查看。现有创建请求保持兼容。
- `DELETE /admin/api/v1/models/{id}` 接收 `{expected_revision}`，执行归档：停用并保留墓碑和账本关联，禁止该公开模型 ID 被重建或由旧权限意外授权新对象。不要物理删除历史账本。已归档对象不能 PATCH 恢复；恢复功能属于后续独立规格。
- 池非空时，修改默认目标返回明确冲突，要求管理员先清空池；不得悄悄改写整个池。修改单账号目标要验证提供商能力，目录与四协议执行必须立即采用新配置。
- `DELETE /admin/api/v1/upstreams/{id}` 接收 `{expected_revision}`，仅当不被任何未归档模型的默认目标或池条目引用时允许归档，否则 409 `upstream_in_use`。归档停用并清除可恢复凭据，保留非秘密历史身份及账本；所有导入替换、OAuth/刷新、目录、测试和绑定操作拒绝复活归档对象。
- 上游列表同样支持 `include_archived=true`；网页可改名称、替换 API Key、停用/启用和归档，Codex 凭据继续使用原有专用入口。归档动作的确认框明确不能恢复，不把“停用”冒充“删除”。
- 所有新写接口要求管理员会话、CSRF/Origin；无效 revision 显式 400、过期 revision 409。同一墓碑的重复归档请求返回可识别结果，不把响应丢失自动解释为失败或重复创建。
- 写事务遵循现有账号锁、admission、池及账本锁顺序；归档/停用前已真正派发的请求可完成并结算，尚未派发的请求要重查，不能继续使用旧快照或扩大员工权限。归档后的 Codex 后台刷新不得复活凭据。
- 迁移是可重试、完整回滚的独立增量；旧数据库升级保留员工 Key、OAuth 来源、池、价格与预算。视图新增字段向后兼容，网页缺能力标志时不显示可用操作。`features.account_lifecycle_management=true` 表示本批入口已经接线。
- 新增有界管理操作审计，包含 actor/action/target/result/time，不记录 Key/凭据。可以独立表实现本批审计，不能声称已完成全局审计系统。

验收：完整创建/修改/启停/归档、引用冲突、CAS、CSRF、员工目录与四协议零旧路由派发、池切换竞争、刷新/重导入竞争、旧库迁移失败回滚/重试、重启、网页窄屏操作和秘密扫描。对在途请求与既有预算结算做回归。

## B：持久化定时测试与监控首批

交付后端、网页与测试。首批复用现有 `local_credential`/`catalog` 测试，明确显示“凭据检查/模型目录可达”，不宣称已经证明模型生成可用。故障账号的生成恢复保留原逻辑，不在本批自动增发有成本的生成请求。

- 新增 `Config.ScheduledTestsEnabled` / CLI `--scheduled-tests-enabled`，默认关闭。运行开关与保存计划独立；关闭时能管理计划但绝不触发测试。
- `GET/POST /admin/api/v1/scheduled-tests`，`GET/PATCH/DELETE /admin/api/v1/scheduled-tests/{id}`。计划字段：`id,name,upstream_id,scope,interval_seconds,enabled,revision,next_run_at,latest_result`；间隔 300–86400 秒，统一以 UTC 保存，不声称 cron/时区已完成。
- 新建 `{name,upstream_id,scope,interval_seconds,enabled}`；PATCH 有 `expected_revision`；DELETE 用 revision 归档停用，不删除历史。GET 列表 `{items:[]}`。写接口沿用管理员 CSRF/Origin。最多 100 个有效计划，全局同时执行最多 2 个，同账号不能重叠测试。
- `GET /admin/api/v1/scheduled-tests/{id}/runs` 返回有界分页记录，最多 100 条一页，采用稳定游标/顺序。记录计划 revision、测试 operation ID、固定结果码、开始/结束/耗时；不保存响应正文或凭据。
- 独立 worker 由 App 启停。到期任务需原子 claim 并保存运行记录，再调用已有健康测试服务；不得复制绕过刷新/代理/SSRF 的网络逻辑。重启把旧 running 标记 interrupted，不重放同一 operation；补跑最多一次并按当前时间计算下次，不能追赶积压形成洪峰。
- 修改/停用/归档或退出时取消自己拥有的测试；结果回写按计划 revision 和 operation 条件更新，旧结果不可覆盖新配置。账号停用或版本变更不自动开启账号或清除冷却。
- 同账号未归档计划不依赖一个用户登录会话持续存在；所有记录可追溯原始管理员操作，后台动作使用固定系统身份。
- 记录每计划最多 200 条完成历史，运行记录不被清理；清理在有界事务内执行并有重启/失败测试。通知、渠道聚合监控、生成测试、告警邮件/静默与 cron 继续作为后续，不标为完成。
- 新页面“定时测试”包含总开关可用性、列表、创建/编辑/启停/归档、结果历史与错误恢复。系统状态能力 `scheduled_tests_configuration`、`scheduled_tests_running` 对旧服务器缺字段时降级。

验收：fake clock 的到期、并发、长测试、取消、重启恢复、写失败、旧结果竞争、历史保留；真实临时 Go 进程对本地假目录上游的定时测试；默认关闭零出站；网页桌面/手机和 0 非预期页面错误。

## C：加密备份与恢复 CLI 首批

独立 `cmd/cpa-cloud-backup` 与 `internal/backup`，不给网页开放读取数据目录的任意路径接口。`create`、`verify`、`restore` 三个子命令，所有路径显式传参，密码只通过 stdin 输入、不放命令参数/日志。

- `create --data-dir <source> --output <new-file>`：只包含本项目 SQLite 一致快照及 root key，不遍历其他文件。用 SQLite 自身快照/备份能力解决 WAL 一致性，不直接拷贝正在变化的 db/WAL 文件；不调用 service.Open，以免备份触发迁移、后台任务或恢复写入。
- root key 在快照前后核对一致，不能输出其内容或摘要。记录自有格式版本、来源程序版本、文件大小/完整性信息于受认证的包内元数据，不把版本字符串当兼容保证。
- 包内容和元数据使用随机 salt、经审阅参数的 scrypt 密钥派生及 AES-GCM 加密认证。拒绝未知格式、截断、错误密码、重复/多余记录和篡改；固定格式只允许两种文件，不接受任意 tar 路径。文件大小/内存/派生参数有硬限额，导入不能由包任意提高 KDF 成本。
- 输出必须是新文件，采用本目录受限临时文件、完整写入/同步后无覆盖提交；失败不得留下看似成功的包。可恢复明文临时快照只能在受限目录短时存在，所有出口清理；不得清理用户输入目录或已有文件。
- `verify --input <file>`：认证、解密并核实结构与 SQLite 完整性，不更改现有实例。不得声称校验通过意味着所有未来版本都能恢复。
- `restore --input <file> --data-dir <new-directory>`：只恢复到不存在的新目录，禁止覆盖真实/已有目录、根目录、路径链接/reparse 或任意外部路径。验证后再发布到新目录；失败保留原实例，清理只能针对本次创建的确切临时路径。
- 恢复后的管理员会话和未完成 OAuth 授权会话作废；对于轮换结果未知的 refresh 状态保持/进入暂停；已完成 OAuth 来源绑定、员工 Key 摘要、加密上游和账本保留。不能因恢复自动重放上游请求或重放旧 refresh token。
- 根密钥仍受 OS/主机管理员边界约束，Windows 权限需与现有密钥保存方式同等或更严格。计划备份、对象存储、密钥轮换、原地升级自动回滚未包含，不宣称 OPS-01 全部完成。

验收必须包含：真实合成数据库（含 WAL 与预算/会员状态）创建加密包→验证→新目录恢复→真实 App 重启/员工 Key 可用；错误密码/篡改/截断、写失败、超限、路径链接、目标已存在、取消、不修改源实例和秘密扫描。补中英文 CLI 使用说明；不得运行真实用户数据目录，不发布新的二进制附件。

## 集成责任与持续范围

任务只在自己的独立工作树提交，不推 main、不自行集成他人的提交、不新增隐藏子任务。各自可以修改完整交付所需文件，但共享 app.go、store.go、web App/api 等的最终合并由总协调者负责，不能删除其他批次接线。完成报告列出提交、文件、命令结果、缺口；正常完成即结束，不靠空转维持运行。

总协调者在三项实现期间继续梳理通用预算的安全扩展，拒绝把估算值冒充硬上界；商业功能先以默认关闭的身份/租户及金额账本规格为依赖，不直接接真实支付。会员条件若没有新证据保持具体阻塞，不重复起研究任务假装实现。普通代码提交按轻量 CI 验收，完成一批只更新对应矩阵状态。
