# 独立实现与来源规则

## 决策

根据用户确认：借鉴 CLIProxyAPI 与 Sub2API 的产品能力，依据公开协议独立实现 CPA Cloud；
自有代码选择开源许可证，保留必要的第三方声明。

不继续沿用原先“基于 CLIProxyAPI 源码重构”的计划。本项目不含归档仓库的代码与 Git 历史。
新仓库是工程上的分离措施，不是许可证豁免证明。

## 规格与实现

- 先描述业务需求、输入输出、故障行为和验收条件，再实现。
- 协议规格记录官方文档 URL、查阅日期、支持范围和已知限制。
- 测试输入和预期自行编写，不搬入参考项目的测试、快照、夹具或迁移脚本。
- 不将原源码交给工具做改名、翻译、语言转换或逐函数重写。
- 不复制原产品图标、截图、界面文案、说明书或数据库实现。
- 第三方库可以使用，但必须记录版本、许可证和随分发所需声明。

## 来源与边界

此前讨论已阅读部分 CPA/CLIProxyAPI 集成代码、CC Switch 源码，以及参考产品说明和许可证。
因此，不宣称严格洁净室开发。后续来源记录用于支持独立实现事实，而非保证不存在争议。
若发现实现包含第三方受保护内容，按来源处理，不能通过删除声明或 Git 历史解决。

公开协议接入仍需核实供应商授权要求；版权以外的专利、商标和服务条款不因独立实现自动消失。

参考依据（研究用，不纳入产品代码）：
- https://www.wipo.int/wipolex/zh/legislation/details/13396
- https://www.copyright.gov/circs/circ61.pdf

## 发布检查

确认自有代码权利与许可证、逐项核查依赖和素材、保留来源与必要声明，
核查仓库历史及产物不含旧项目代码或秘密，再决定是否公开发布。
