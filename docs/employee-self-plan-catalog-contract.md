# ID-05 / BILL-03 employee self plan-catalog contract

Status: independently specified development-preview increment, default off. This extends the [employee self-service foundation](employee-self-service-foundation-contract.md) and the [single-instance billing contract](single-instance-billing-contract.md). The [existing-subscription status view](employee-self-subscription-status-contract.md) reads historical records; this catalog instead shows only the current revision of currently enabled plans when commercial execution is enabled. Neither view grants an entitlement or lets an employee purchase.

## Provenance, sources, and activation

This contract and its future implementation/tests are CPA Cloud-authored from functional requirements and public documentation. They are not copied, translated, or ported from archived CPA, CLIProxyAPI, Sub2API, or neighboring reference repositories. Previously viewed reference code means this work is not represented as strict clean-room development. Public references consulted on 2026-10-02: [Go `net/http`](https://pkg.go.dev/net/http), [Go `database/sql` transactions](https://pkg.go.dev/database/sql#DB.BeginTx), [Go authenticated encryption (`cipher.AEAD`)](https://pkg.go.dev/crypto/cipher#AEAD), [SQLite isolation](https://www.sqlite.org/isolation.html), and [SQLite `SELECT` ordering/limits](https://www.sqlite.org/lang_select.html). Existing Go, SQLite-driver, React, and test dependencies retain their own recorded licenses; this increment adds no dependency, SDK, migration, or asset.

`--employee-self-plan-catalog-enabled` is a new false-by-default startup opt-in. It requires `--employee-self-service-enabled`; an invalid missing prerequisite fails startup before changing stored state. It does not require or switch on any wallet-read, subscription-status, or commercial-execution capability. When off, the route is absent (404), the self-session capability `employee_self_plan_catalog` is false, and the browser makes no catalog request. Existing administrator, model, wallet, and subscription-status behavior is unchanged.

Only an enrolled, currently active employee with a valid self-service session may read. The existing self boundary checks the optional same-origin `Origin`, keyed session cookie verifier, expiry, and employee status. An administrator cookie, model Bearer Key, anonymous caller, disabled employee, or another employee's session cannot substitute. The verified session alone supplies employee identity; the catalog is otherwise common to authorized employees, not personalized or an owner-specific price. No query or cursor may select an employee, account, Key, resource, subscription, connector, or plan. Logout/revocation invalidates first reads and continuation.

## `GET /self/api/v1/billing/plans?currency=USD[&limit=20][&cursor=...]`

`currency` is required and is exactly three uppercase ASCII letters. The first page may omit `limit` (20) or provide one canonical decimal integer from 1 through 50. A continuation must explicitly repeat the same limit and currency. Unknown/duplicate query keys, malformed escaping, empty values, noncanonical limit, oversized query/token, any selector, and any request body (including unknown-length transfer) return fixed `400 invalid_request`. The query and cursor have explicit length bounds. `Cache-Control: no-store` applies to success and errors.

The exact success shape when commercial execution is enabled is:

```json
{
  "currency": "USD",
  "available": true,
  "items": [
    {"plan_id":"plan_example","name":"Internal monthly","interval":"monthly","price_micro":"1000000","credit_micro":"1200000","revision":2}
  ],
  "next_cursor": null
}
```

`items` is always an array of at most 50. It contains only currently enabled `financial_plans` rows in the requested currency, with opaque plan ID, current administrator-entered name, `one_time|monthly` interval, canonical positive decimal string micro amounts, and current positive safe-integer revision. The current row is mutable under administrator revision/CAS; this is not a historical price ledger. `available:true,items:[]` means the commercial switch is on but no enabled plans match this currency. It does not mean a wallet exists or the employee can pay.

When the existing `financial_settings.enabled` commercial-execution switch is off at this page's read snapshot, the response is exactly `{ "currency":"USD", "available":false, "items":[], "next_cursor":null }`. The browser clears any previously displayed quote and explicitly says the current catalog is unavailable. This applies to a first page and to a continuation after the switch turns off; no old price or plan row is returned. The service does not enable commercial execution or create a plan/account in order to answer. The response has no account, subscription, operation, ledger, payment, connector, employee, Key, resource, or entitlement fields. It is information for discussion with an administrator, not an employee checkout or a promise that a plan will remain enabled or priced the same.

Rows are ordered by immutable plan `id TEXT ASC`; continuation uses strict `id > last_id` keyset and `limit+1` lookahead under the same currency/enabled filter. ID order is stable, **not** chronological or price order. Each page is a fresh SQLite snapshot. Concurrent admin edits may change a row's current revision/price, disable a plan, or insert a row between pages; the API does not promise a complete cross-page snapshot or a locked quote. The browser labels values as observed at read time, never as purchase availability.

The cursor is versioned, purpose-separated authenticated encryption with the installation's existing persistent AEAD and a fresh nonce. It contains only employee ID, current self-session selector, currency, initial-page issue time, limit, and last returned plan ID. It is not stored in the database or browser storage and does not reveal a plan ID in the URL. Canonical encoding/structure, authentication, purpose, version, same employee/session/currency/limit, ID shape, issue time not in the future, and at-most-15-minute age are checked before storage access. Tampered/truncated/foreign-installation/foreign-session/foreign-currency/foreign-limit/expired cursors return fixed `400 invalid_request`; generation failure returns fixed `503 storage_unavailable` before success output. An authenticated cursor does not lock commercial execution: every page rereads the switch.

## Bounded read, validation, and failure

Each page uses one at-most-five-second read-only transaction. It validates relevant existing financial/commercial schema and the single commercial-settings row, reads the execution switch and (only when on) at most `limit+1` current matching plan rows. All predicates and ordering are in the database query. Every selected row including lookahead must have expected SQLite storage types, a valid opaque ID and bounded nonblank name, exact currency, allowed interval, enabled integer `1`, positive bounded integer micro amounts, valid revision, and canonical UTC created/updated timestamps with `updated_at >= created_at`. It does not read historical subscription snapshots to manufacture an offer.

Settings/schema/selected-row corruption, SQL query or scan failure, iterator/close/commit failure, cancellation/deadline, or cursor generation failure returns fixed sanitized `503 storage_unavailable` with zero partial items. Check context again after successful read-only commit and immediately before writing the first success byte. No DDL, financial write, persistent personal fact, per-request admin HTTP hop, payment, or upstream request occurs. No key, auth header, upstream token, prompt, model response, cursor content, or raw SQL error is logged.

## Browser and acceptance boundary

The `/self/` page renders a separate catalog control only when `features.employee_self_plan_catalog=true`. It never fetches plans on mount/login: an employee explicitly enters one uppercase three-letter currency and clicks. Results/cursor remain only in component memory. Changing currency or self account/session, logout, unmount, or any failed page read clears previous quotes and cursor. Abort plus generation checks prevent late responses from repopulating stale data; a next-page click repeats the bound currency/limit and appends only to the current view. Desktop and 390px layout clearly distinguish unavailable, available-empty, and current results. Copy states that purchase/cancellation/renewal still requires an administrator and that displayed values are not an entitlement or durable quote.

This increment does not create, buy, cancel, or renew subscriptions; offer trials/employee checkout; modify prices or credits; infer access rights; or contact a payment provider.
