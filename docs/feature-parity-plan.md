## 1. 范围、状态与架构边界

目标是对齐固定快照中经路由或源码文件验证的产品能力。注册、预算、限流、多租户、账单、订阅、充值、支付和兑换均在总范围内；默认产品配置仍是“一家企业、一套实例、管理员建员工”的内部企业模式，公开注册、商业计费与多租户能力默认关闭。启用外部经营模式前必须形成身份、财务、隐私、风控与合规设计及验收记录。

本文不是“参考产品全部功能已经穷举”的声明。固定快照仍可能有未从入口显现的后台任务、配置开关或提供商特例；后续围绕该阶段的缺失证据定向补查，并把新增发现补入带编号矩阵。已核实的来源与接口结论复用，避免每个任务重复盘点整个参考仓库。

状态含义：

- **已实现**：CPA Cloud 当前源码已有实现，并有仓库内测试或集成记录；只代表所列子集。
- **实验**：源码存在且默认关闭、协议范围受限或没有真实供应商验收。
- **部分实现**：五个交付环节中已有明确子集，仍有实质能力或生命周期未接通；不能按整项完成计数。
- **待实现**：产品需求已确认，但尚无可验收实现。
- **需协议核实**：除工程实现外，还必须先取得逐提供商、逐流程的独立协议规格及允许使用方式；不能从参考实现存在推导为可直接交付。

架构保持一个 Go 服务进程承载员工鉴权、策略、调度和上游执行，模型请求不经过第二层业务代理。SQLite 是当前单机预览存储；未来 PostgreSQL、Redis、对象存储可作为持久化、协调、缓存和备份扩展，不能变成每次模型调用的多跳代理。管理员权限与员工 Key 严格分权；员工 Key 只存 keyed digest，可恢复的上游凭据加密；日志不得含认证头、Key、Token、提示词、响应或秘密配置。

## 4. 分阶段执行与出口条件

MEM-03/04 的接入限制于 2026-09-23 复核 [Anthropic 认证与凭据政策](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use)及 [Gemini CLI FAQ](https://geminicli.com/docs/resources/faq/#why-cant-i-use-third-party-software-like-claude-code-openclaw-or-opencode-with-gemini-cli)。这是当前管理员订阅账号池方案的具体阻塞，不是对所有 OAuth 或未来供应商安排的普遍法律判断。详细出口条件见[会员接入记录](research/membership-provider-readiness.md)；两项继续保留在总目标中。

### M0：Responses 与 Codex 工具首批

实现 `POST /v1/responses` 和 Codex 原生 function tools/function_call_output/tool result SSE，严格按 [Responses 首批契约](responses-preview-contract.md) 的子集执行。默认关闭的加密有状态资源与后台创建/轮询/取消现已接入，重启对已派发任务只记 interrupted、不重放；入口仍逐字段拒绝不能完整持久化的后台语义。状态继续为实验：真实会员账号未验证，托管工具白名单为空，后台流游标/WebSocket 仍缺，preview.3 不包含此功能。

### M1：三家会员生命周期与原生协议

优先推进 Codex 网页授权、自动刷新、撤销和会员模型发现，并完成 Claude、Gemini 的导入/授权/刷新/调用规格与实现；同时完成 Messages、Gemini 和 Responses 的明确子集。会员文件导入从实验转为受支持前，必须有真实账号兼容证据或明确保持实验。出口要求：每种协议独立的字段/事件支持表和真实或官方沙箱证据，不能用一种协议的通过代表另一种。

### M2：可靠账号池、治理与可核算运行

账号/分组、路由、冷却、派发前换号、会话、治理、可靠用量事实、通用预算策略、定价快照和日/月导出已有源码增量。供应商配额/重置感知、Key 独立协议/模型/IP 策略、统一审计、监控告警及广泛模型安全上界仍是 M2 出口；并发、流式中断、持久化失败、重启恢复和脱敏检查继续要求自动化。

### M3：可选商业化、多租户与运维闭环

本轮已建立默认关闭的单实例不可变金额账本、套餐/订阅、充值/兑换/退款和通用签名 callback，并接入 Windows DPAPI 自动备份/演练；这不是生产支付渠道或完整灾备。多租户本轮明确不做，注册、自助门户、真实渠道沙箱、自动续期/到期、跨机密钥恢复、对象存储与升级回滚仍是后续出口；内部企业部署默认不暴露注册/支付入口。

### M4：媒体、运营与规模扩展

补齐图片、视频、语音、Realtime/WebSocket、托管工具、公告通知、插件，以及可选 PostgreSQL/Redis/对象存储和多节点协调。出口要求：长连接与异步任务资源回收、对象生命周期、插件隔离、故障注入和规模基准。数据库/缓存扩展不得改变模型请求由 CPA Cloud 单一 Go 进程直接执行上游的边界。

## 5. 每个编号的交付模板

实现任何矩阵编号前，先提交独立规格：业务场景、公开协议来源及查阅日期、输入输出、权限、状态机、存储/迁移、失败和取消、日志与指标、兼容边界、回滚。涉及信任边界或职责移动时先写 ADR。

每个编号的合并门槛：

1. 单元、HTTP/存储集成和故障模式测试；协议功能还需流式拆包、取消和工具/多模态契约测试。
2. 安全日志脱敏审阅；扫描数据库、WAL、备份、日志和浏览器响应中不应出现的秘密或内容。
3. 运行仓库实际配置的 lint、类型检查、测试与安全检查命令；未配置的检查应记录缺口，不能写成已执行。
4. 更新协议支持表、管理员/员工文档、迁移与回滚说明、`integration-status.md`。
5. 演示备份/恢复或配置回滚；新增持久化结构必须覆盖升级中断与重试。
6. 将状态由“待实现/需协议核实/实验”改为“已实现”时，链接到测试和集成证据，并保留仍不支持的边界。

## 6. 协议与法律判断规则

会员网页登录、Token 刷新、Cookie/设备流程和非公开端点必须逐提供商形成独立协议规格；参考快照的路由只能证明产品表面存在该能力。公开资料未显示 client 注册方式时，只能记录“当前证据不足、需核实”，不能据此作普遍合法或不合法结论。支付、注册和多租户同样需要按启用地区、渠道与部署模式核实，而不是从默认内部模式推导为永久排除。
