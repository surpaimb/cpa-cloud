## Scope / 范围

This release is limited to a **single-tenant Linux amd64 Go server, browser admin
console and offline backup CLI**. The user authorized integration and subsequent
release of the implemented scope with known failures and incomplete features
disclosed. That decision is not an all-green CI claim or full-product production
safety acceptance. Windows/macOS/ARM and desktop installers are outside this
release. Employee-client source remains in Git; no employee installer or real
application acceptance is supplied by this package.

本版仅面向 **Linux amd64、单租户 Go 服务端、浏览器管理后台及离线备份 CLI**。
用户已授权在披露已知失败和未完成能力的前提下集成、后续发行已实现范围；这不代表全 CI
绿色或完整产品生产安全验收。Windows、macOS、ARM、桌面安装器不属于本次发行。
员工客户端源码保留，但本包不交付员工安装器，也不证明对真实应用执行配置已验收。

The planned payload is `cpa-cloud_v0.1.0_linux_amd64.tar.gz`, with an archive
SHA256 sidecar. It contains `cpa-cloud`, `cpa-cloud-backup`, built `web/` assets,
version/build information, inventories/checksums, documentation and required
third-party notices. Compilation consumes source, locked Go/Bun dependencies,
the fixed toolchains and target OS/architecture, and the observed static Web
build. Real keys, custodians, deployment hosts and live data are **not** compile
inputs. Go/Bun are not required to run the resulting package.

计划产物为上述 tar.gz 及独立 SHA256 校验文件，内含两个命令、Web 静态资源、构建与版本

## Installation configuration / 安装时配置

Extract the complete package into a versioned application directory and retain
all notices. Keep data and backups outside it. There is **no unified `--config`
file or installation wizard**. The operator supplies CLI flags and protected
systemd credential references; this document does not provision a host.

完整解压到独立版本目录并保留全部声明；数据与备份放在程序目录外。当前没有统一
`--config` 文件或安装向导，运维通过 CLI flags 和受保护的 systemd credential 引用配置，
不由编译过程写入真实部署参数。

| Setting / 配置 | Contract / 约束 |
| --- | --- |
| Data / 数据 | `--data-dir` selects a persistent private directory; initialize once with `--init`, reading the administrator password from stdin, then run against the same directory. / 私有持久目录，初始化与运行使用同一目录；密码不放 argv。 |
| Web | `--web-dir` points to the extracted `web/` directory. / 指向解压后的静态资源目录。 |
| Listen / 监听 | Default `--listen=127.0.0.1:8787`; remote access requires a configured TLS boundary. Direct TLS uses `--tls-cert` and `--tls-key`; trust a reverse proxy only through explicit `--trusted-proxy-cidr` values. / 回环默认；远程访问须配置 TLS，代理信任须显式指定。 |
| Installation root M / 安装根 | Explicit `--master-key-provider=linux-systemd-credential-v1`; systemd supplies fixed credential `cpa-cloud-master-key`, authenticated against `master-key-binding.json`. No secret argv/plain environment value. / 认证已有绑定，不降级普通文件 reader。 |
| Backup wrapping root W / 备份根 | Independent fixed credential `cpa-cloud-backup-wrapping-key`; M/W share the installation instance UUID, but must have different key IDs and key bytes. / M/W 共用安装实例 UUID，但 key ID 与密钥字节必须不同，不把 W 放入 SQLite 或密文旁。 |
| Backups / 备份 | `--automated-backups-enabled` is an explicit opt-in; `--automated-backups-output-dir` selects the restricted output root. Configure plan, destination, retention and off-host custody deliberately. / 显式配置计划、目标和保留；本地保留不等于异机灾备完成。 |
| Instance / 实例 | `--instance-id` is a public runtime health identity, valid only while running; omit it for `--init` and `--check-initialized`. It does not create or replace the credential's authenticated installation identity. / 不用于初始化或替代 credential 身份。 |
| Self service / 自助 | Off by default; `--employee-self-service-enabled` and any further capabilities are separate opt-ins. / 默认关闭，不自动开启商业或自助能力。 |

For the protected Linux mode, the deployment chooses and verifies the
`LoadCredentialEncrypted=` host/TPM policy and fixed non-root service identity.
Only references to separately protected M/W capsules belong in unit
configuration. `CREDENTIALS_DIRECTORY` is systemd's runtime path interface, not a
secret-value environment variable. The reader does not attest the original
encryption/custody policy; real-host activation and recovery authorization remain
operator responsibilities. The default `preview-file-v1` mode is retained for
compatibility and is not proof of protected systemd custody.

Linux 受保护模式要求运维配置并核实固定非 root 服务身份、M/W capsule 的
`LoadCredentialEncrypted=` 引用及 host/TPM 策略。reader 不能证明 capsule 原始加密与
保管策略；真实主机激活、授权和恢复材料仍需独立核实。兼容的默认 `preview-file-v1`
不等于 systemd 受保护保管。安装细节见[主密钥契约](../linux-systemd-master-key-provider-contract.md)
和[备份 W 契约](../adr/0005-linux-systemd-backup-wrapping-key.md)。

## Backup and recovery / 备份与恢复

- Password `create` / `verify` / `restore` and key-material commands retain their
  existing contracts. Passwords use stdin, never argv. / 旧口令路径保持原合同。
- **systemd v3 has only `systemd-v3-verify` and `systemd-v3-restore` in the CLI.**
  The service's configured automated backup plan creates v3 packages; password
  `create` is not a v3 creation command. / v3 由服务备份计划创建，不虚构 v3 CLI create。
- Offline v3 requires its dedicated recovery unit/user, protected M/W references,
  retained binding seed, exact public identity/version arguments, isolation and a
  nonexistent target. It does not use the active service credential directory,
  read stdin, start the business application or switch traffic. Follow the
  [offline recovery contract](../linux-systemd-offline-recovery-cli-contract.md).
- Restore errors, cancellation or cleanup errors do **not** prove rollback.
  A target may already have been validly published. Stop and independently inspect
  the result; do not automatically retry, overwrite, delete or switch traffic.
  / 错误不等于回滚，须人工核实是否已发布，不自动重试或覆盖。

See [backup/restore usage](../backup-restore.md). Synthetic systemd/VM rehearsals
are bounded regression evidence, not actual deployment custody, production
RTO/RPO, real M1→M2 rotation or old-backup anti-resurrection acceptance.
