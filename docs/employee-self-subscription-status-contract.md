# ID-05 / BILL-03 employee self subscription-status contract

Status: independently specified development-preview increment, default off. This extends the [employee self-service foundation](employee-self-service-foundation-contract.md), the [single-instance billing contract](single-instance-billing-contract.md), the [frozen subscription-period contract](subscription-period-expiry-contract.md), and [manual renewal](subscription-manual-renewal-contract.md). It is a minimal read of existing subscription records, not an entitlement, complete bill, payment result, or offer to purchase. GOV-02 remains open.

## Provenance and activation

This contract and the new code/tests are CPA Cloud-authored from the functional requirements and public documentation, not copied, translated, or ported from archived CPA, CLIProxyAPI, Sub2API, or neighboring reference repositories. Previously viewed reference code means this work is not described as strict clean-room development. Public references consulted on 2026-10-02: [Go `net/http`](https://pkg.go.dev/net/http), [Go `database/sql` transactions](https://pkg.go.dev/database/sql#DB.BeginTx), [Go authenticated encryption (`cipher.AEAD`)](https://pkg.go.dev/crypto/cipher#AEAD), [SQLite isolation](https://www.sqlite.org/isolation.html), and [SQLite `SELECT` ordering and limits](https://www.sqlite.org/lang_select.html). Existing Go, SQLite-driver, React, and test dependencies retain their recorded licenses; this increment adds no dependency, SDK, migration, or asset.

`--employee-self-subscription-status-enabled` is a new false-by-default startup opt-in. It requires `--employee-self-service-enabled`, but does **not** require either wallet-read flag or `financial_settings.execution_enabled`. An invalid missing self-service prerequisite fails startup before changing stored state. When off, the new route is absent (404), the self-session capability is false, and no subscription read is scheduled. Turning commercial execution off does not delete or conceal already recorded subscriptions; the new read remains available if its own opt-in is on. Existing balance/activity, administrator, and model routes retain their prior behavior.

Only an enrolled, currently active employee with a valid self-service session may read. The existing self boundary checks the optional same-origin `Origin`, keyed cookie verifier, session expiry, and employee status. An administrator cookie, model Bearer Key, anonymous caller, disabled employee, or another employee's session cannot substitute. The verified session alone supplies employee identity. No query or cursor may select an employee, account, Key, resource, plan, or status. Logout and session revocation invalidate both first reads and continuation.

## `GET /self/api/v1/billing/subscriptions[?limit=20][&cursor=...]`

The first page may omit `limit`, defaulting to 20, or provide one canonical decimal integer from 1 through 50. A continuation must explicitly repeat the same limit. The bounded base64url `cursor` is only a continuation token; unknown or duplicate query keys, malformed encoding, empty values, noncanonical limits, oversized query/token, and any request body (including unknown-length transfer) return fixed `400 invalid_request`. `Cache-Control: no-store` applies to success and errors.

Successful response shape is exactly:

```json
{
  "items": [
    {"subscription_id":"sub_example","interval":"monthly","status":"expired","started_at":"2026-08-31T12:00:00Z","period_end_at":"2026-09-30T12:00:00.000000000Z","cancelled_at":null}
  ],
  "next_cursor": null
}
```

`items` is always an array of at most 50. Each item has only the opaque existing subscription ID, frozen `one_time|monthly` interval, effective `active|cancelled|expired` status, canonical UTC start, nullable frozen period end, and nullable cancellation time. A still-stored active monthly row is projected `expired` at or after its end without writing it; a cancelled row remains `cancelled` even after that end. `one_time` has no period end and does not become expired. Old cancelled, one-time, expired, predecessor, and successor records remain readable; this read does not renew or change them. The page conveys neither current model access nor usable credit. It excludes plan name/ID, price, credit, currency/amount, wallet/ledger/operation IDs, payments, renewal links, and other employees' details.

Rows are ordered by immutable subscription `id TEXT DESC`, with strict `< last_id` keyset continuation and `limit+1` lookahead. ID order is stable, **not** chronological order. Every page is a fresh read-only SQLite snapshot; posting/cancellation/expiry between pages may change later effective status or place new rows behind/ahead of the position. The API does not promise a cross-page complete snapshot. It captures one UTC `asOf` instant per page for consistent status projection within that page, but does not expose that instant as another field.

The cursor is versioned, purpose-separated authenticated encryption using the instance's existing persistent AEAD with a fresh nonce. It contains only employee ID, current self-session selector, fixed initial-page issue time, limit, and last returned subscription ID. It is not stored in the database or browser storage and does not reveal IDs in the API URL. Canonical encoding/structure, authentication, purpose, version, same employee/session/limit, ID shape, issue time not in the future, and at-most-15-minute age are checked before storage access. Tampered/truncated/foreign-instance/foreign-session/expired cursors return fixed `400 invalid_request`. Cursor generation failure returns fixed `503 storage_unavailable` before success output.

## Bounded storage read and failure behavior

Each page uses one at-most-five-second read-only transaction. It validates the existing financial account and subscription schema/indexes, then selects at most `limit+1` subscriptions whose `account_id` joins directly to a matching `financial_accounts` row with `owner_kind='employee'` and `employee_id` from the verified session. A Key-owned account, resource-owned account, or another employee's account cannot enter the result. Every selected account row must have the canonical direct-employee owner key, null Key ID, empty resource fields, and matching subscription/account currency. Every selected subscription, including lookahead, must have a valid identifier, expected storage types, canonical UTC timestamps, allowed interval/state/null combinations, valid monthly frozen end, and cancellation not before start, consistent with the existing subscription lifecycle. No unrelated plan, price, credit, payment, or ledger values are returned.

Iteration, row scan/shape, close, context cancellation/deadline, and commit are checked before the first success header or byte. Missing/malformed relevant schema, malformed selected row/account, SQL/commit failure, timeout, or cancellation returns fixed sanitized `503 storage_unavailable` with no partial item response. No DDL, account creation, financial write, full-ledger sum, upstream request, or per-request admin HTTP hop occurs. No key, auth header, upstream token, prompt, model response, cursor content, or raw SQL error is logged.

## Browser and acceptance boundary

The `/self/` browser page shows a separate capability-gated subscription-status control only when `features.employee_self_subscription_status=true`. It never fetches subscriptions on mount, login, or simply opening the page: the employee explicitly clicks to read. Results and continuation stay only in component memory. Changing self account/session, logout, unmount, or any failed page read clears prior results/cursor; abort plus request-generation checks prevent a late response from repopulating stale state. A next-page click repeats the bound limit and appends only to its still-current view. Desktop and 390 px layouts show empty, active, cancelled, and expired states clearly without suggesting an entitlement or purchase action.
