# ID-05 employee self request activity contract

Status: independently specified development-preview increment, default off. This extends the [self-service foundation](employee-self-service-foundation-contract.md), [password change](employee-self-password-change-contract.md), and [Key inventory](employee-self-key-inventory-contract.md). ## Scope and provenance

An active, admin-enrolled employee with a valid independent self session may read a minimal history of **their own** model requests. The server obtains employee identity exclusively from the verified session. Admin sessions, employee API Keys, anonymous callers, and another employee's cursor cannot substitute. The existing `--employee-self-service-enabled` flag gates the page and endpoint; its default remains off. This increment has no DDL, admin configuration, Key mutation, model-dispatch or ledger-write change, billing, membership, payment, external service, package, or deployment.

The new implementation and tests are authored from this contract and existing CPA Cloud specifications, not copied or ported from archived CPA, CLIProxyAPI, Sub2API, or adjacent reference repositories. Public protocol references: [RFC 3339](https://www.rfc-editor.org/rfc/rfc3339), [Go net/http](https://pkg.go.dev/net/http), [Go database/sql](https://pkg.go.dev/database/sql), [SQLite SELECT](https://www.sqlite.org/lang_select.html), and [SQLite isolation](https://www.sqlite.org/isolation.html). Existing Go, SQLite, React, and test dependencies retain their recorded third-party licenses; no third-party license is transferred to this source.

## GET /self/api/v1/usage/requests

This read-only `GET` uses the existing `requireSelf` boundary, including optional same-origin check, live session digest and expiry, and current active employee state. No body is accepted, including unknown-length bodies. Query keys are only `from`, `to`, `limit`, and `cursor`, each at most once. Unknown, duplicate, empty, malformed, or oversized parameters return sanitized `400 invalid_request` and no data. `from` and `to` must appear together. They are RFC3339 timestamps with whole-second precision and explicit zone; normalized UTC values define the half-open `[from,to)` window, with `from < to` and duration at most 31 days. Without them, the first page uses a server-frozen recent 24-hour window ending at the next UTC second. A cursor carries that fixed window; a following request may omit `from`/`to`, or supply an exact normalized match. There is no employee selector.

Absent `limit` means 20; explicit limit is unsigned ASCII decimal `1`–`50`, with no leading zero, sign, or whitespace. A cursor is a canonical, bounded, versioned base64url payload authenticated with a purpose-separated keyed digest. It binds the verified employee, fixed window, and last emitted `(started_at,id)` position. Forged, malformed, cross-employee, mismatched-window, and stale-version cursors fail with `400 invalid_request`. It is a page position, not an authorization token; every database query still filters by the current verified employee ID. A later page may choose a different valid limit without changing the window.

The `200` response is exactly `{ "items": [...], "next_cursor": string|null }`. Each item is exactly `{ "id", "key_id", "model_id", "status", "started_at", "finished_at" }`; `finished_at` is null only for `pending`. Status is one of `pending`, `succeeded`, `failed`, `cancelled`, `interrupted`. Times are normalized UTC RFC3339, preserving nanosecond precision. No provider, account/upstream, attempts, tokens, cost, price, billing, policy, secret, prompt, response, or error text is included. `Cache-Control: no-store` applies to success and failure.

Query order is descending by actual UTC `started_at`, then binary descending `id`. Since ledger timestamps are canonical UTC RFC3339Nano with variable fractional width, the query compares a normalized nine-digit fractional time key rather than raw timestamp text. The cursor key uses the same ordering. A bounded SELECT reads at most `limit+1` rows to determine `next_cursor`; it validates every scanned row, including the sentinel, and closes the result before sending any success bytes. Missing/corrupt schema, wrong field type, invalid ID/model/status/time, inconsistent pending/finished state, read/scan/iteration/close failure, and cancellation fail closed with fixed `503 storage_unavailable` and no partial items. No total count or cross-employee existence hint is returned.

Each page is one SQLite SELECT, but pages are **not** a snapshot. A concurrent insertion before the cursor position may be absent from subsequent pages; one after the position may appear. A request that changes status after an earlier page may show its new status if reread. The client can restart at page one. Session expiry, logout, employee disable, and restart-invalidated sessions return authorization failure without reaching the history read.

## Browser, retention, and release boundary

The existing `/self/` page shows a read-only compact list and explicit “load more” action at desktop and 390 px. It clears request history on login, logout, session/account change, and any failed page; late responses must not restore stale data. It does not persist session, cursor, or history in browser storage, URL, or service-worker cache. The existing admin usage API remains unchanged.

Source data is existing `accounting_requests` rows. This feature adds no persisted personal data and no deletion or retention timer. Existing ledger, WAL, backups, and restored snapshots follow their base retention behavior; hiding a row here is not forensic erasure. Operators must settle notice, role access, backup/restore, and retention before enabling in production. GOV-02 remains open; until then, leave self-service off for production.
