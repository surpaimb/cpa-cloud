# 第一版产品与架构计划

状态：开发预览，2026-09-25 更新。用户已要求将适合本项目边界的参考产品能力纳入 CPA Cloud 实现范围，不能把最小 API Key 预览当作产品完成。分期需求与验收见 [完整功能对齐计划](feature-parity-plan.md)，实际验证与未完成项见 [集成状态](integration-status.md)。

## 产品范围

默认一家企业部署一套。管理员创建员工并交付 Key，员工使用自己的 AI 工具。普通自助注册、员工门户、配额、订阅、充值、支付、兑换与运营管理仍在规划；通过运行模式和权限配置提供，不强迫公司内部部署启用收费流程。严格多租户、租户域名和 SSO 不属于当前实现目标；多节点仍需单独设计，不能暗示当前已有跨实例一致性。
独立开源项目，吸收 CLIProxyAPI 的协议接入能力和 Sub2API 的管理体验作为产品目标；
实现依据公开协议和本项目规格，不复用这两个项目的实现。

## 架构提案

单个 Go 服务承载管理 API、静态网页和模型 API，但管理员会话与员工 Key 严格分权。
React 网页构建产物由服务通过 --web-dir 提供；SQLite 用于预览单机持久化；Docker Compose 部署仍待实现。
上述技术选型为提案，待详细设计与验证。

模型请求：客户端 → HTTPS 入口 → 员工与 Key 鉴权 → 协议/模型有效权限 → 同协议转发或显式 wire 转换 → 上游。
以上鉴权和执行在一个服务进程中，不引入 CPA Cloud 到另一个模型代理的 HTTP 跳转。
若部署使用 TLS 反向代理，应如实标注这一网络跳点，不混同于第二层模型业务代理。

## 功能优先级

| 阶段 | 范围 | 验收 |
| --- | --- | --- |
| P0 账号与工具闭环 | 三家会员授权/导入/刷新、API Key、Responses/Messages/Gemini/Chat、工具调用、模型能力目录与实际客户端验收 | 各提供商单独完成鉴权生命周期、工具回合、取消及失败测试；真实验证另列 |

| P2 平台管理与运营 | 用户/角色/部门、Key策略、可选配额与限流、用户门户、订阅/充值/支付/兑换、审计与报表 | 默认内部模式可关闭收费；计费幂等、回调验证、权限与隔离可验收 |

| 暂缓专用员工端 | 员工优先直接使用 CC Switch 或自行配置工具，专用客户端暂不排期 | 不强制安装，和标准客户端执行相同服务端权限 |

第一版目标覆盖 ChatGPT/Codex、Claude、Gemini 的会员凭据导入或授权，以及 API Key 接入。三家的授权、导入、刷新与请求能力分别验证，未通过不得宣称支持；
需逐提供商核实公开文档、官方客户端可观察协议及适用条件。缺少稳定公共文档时单列实验与待核实项，不把协议研究等同于实现，也不把缺少文档推导成普遍法律结论或从完整需求中删除该功能。

## 核心业务约定

- 员工字段：姓名、可选部门、备注和启停状态；默认内部模式由管理员创建。自助注册、用户门户和充值属于后续可选运营能力。
- 每个员工可有多个 Key，分别命名用途；默认不绑定硬件。Key 默认永久有效（expires_at = NULL），可选设置到期时间并可单独撤销；正常重启、升级和上游凭据更换不使员工 Key 失效。
- 停用员工使所有关联 Key 失效。明确正在流式输出的请求在撤销时如何处理，并单独测试。
- 模型权限支持员工级与 Key 级的“全部可用”或显式列表；实际权限取员工策略、Key 策略与当前有效路由的交集，目录不得暴露未授权模型。
- Key 明文只在创建时交付，不提供再次读取接口；丢失时生成新 Key 并撤销旧 Key。
- 统计以请求、员工、Key、模型、上游为维度；区分输入、输出及上游提供的缓存 Token。
- 成本估算不等于实际账单；未知用量不能伪造为精确值；重试不能重复计算员工请求数。
- RPM/并发硬限制和有限模型/请求范围的固定模型硬预算已经以默认关闭方式接线；TPM/成本通用上界仍只有观测或局部能力，不能宣称通用预算完成。可选支付与多节点分别完成账务及一致性边界后再实现；严格多租户不在范围内。

## API 兼容目标

逐项依据官方文档设计并验证 `/v1/models`、`/v1/responses`、`/v1/chat/completions`、`/v1/messages` 与 Gemini `v1beta`。
不是一次宣称全部兼容：每种协议需单独覆盖流式、工具调用、错误、取消和模型支持范围。
优先同协议上游转发；跨协议转换须有独立规格和测试，不静默丢弃不能表达的能力。

已形成[核心设计提案](core-design.md)和[验收矩阵](acceptance-matrix.md)，首轮预览及多批增量已实现；每项真实范围与未完成部分以[集成状态](integration-status.md)为准。

3. 数据模型、事务、撤销生效确认及鉴权缓存一致性。
4. 首个协议与提供商、模型目录、错误映射和流式生命周期。
5. 用量事件、幂等键、故障恢复、保留期及审计脱敏。
6. 开源许可证权利人署名和发布前依赖清单。
