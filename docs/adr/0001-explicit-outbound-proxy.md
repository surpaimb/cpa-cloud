# ADR 0001：显式出站代理与目标信任边界

日期：2026-09-23。状态：本批架构决策已采用，服务集成尚未完成；不表示代理功能已可用。

## 背景

PROXY-01 要求管理员将上游账号绑定到指定网络出口，包含企业 LAN 代理。当前模型请求由 CPA Cloud 单个 Go
进程直接执行，生产端点只允许 HTTPS 公网目标；不能通过新增代理绕开既有目标地址和证书校验。

## 决策

员工仍只向 CPA Cloud 交付员工 Key。鉴权、模型权限、调度、用量和上游执行保留在同一 Go 进程，管理 API
不进入每次模型调用链路。选择代理后，网络路径明确增加 HTTPS CONNECT 跳点：CPA Cloud → 管理员指定的代理
→ 上游 TLS 服务。该代理是网络出口，不能承担本服务的员工鉴权、账号选路或模型协议转换。

管理员对代理地址、认证及账号绑定拥有显式写权限。代理目录接受固定 `public` 或 `private` 地址域；private
只允许 RFC1918 和 IPv6 ULA，每次建连重新检查全部 DNS answers，不允许跨域重绑定、混合域、CGNAT、链路本地
或云元数据地址。环回只由测试开关允许。目标仍须符合现有公网限制，LAN 代理权限不传递给模型目标。

第一批只接 HTTPS CONNECT 与 API Key 账号。代理 TLS 和隧道内目标 TLS 均验证原始 hostname，CONNECT 使用本机
已验证目标的字面 IP，避免远端解析绕过地址检查。不读取环境代理，不跟随重定向，不允许证书跳过、生产 CA
覆盖或失败后丢弃账号绑定改为直连。Codex 的 OAuth、刷新、目录及模型路径尚未统一出口，绑定接口明确拒绝。

代理可见目标地址、时长和流量元数据；模型认证与正文由目标 TLS 保护。代理用户名/密码只用于代理握手，
以独立 AEAD purpose 和 proxy ID 绑定后存储，管理响应不读回。员工 Key 不发送给代理或上游。

账号出口变更递增绑定账号的 revision，与代理 connection revision 在同一事务中提交；派发前复核版本。
已有请求可以在原连接结束，后续不隐式重放。已有故障隔离不会因改出口而清除，恢复仍需要对应版本的证明
或管理员显式操作。账号池原来可以选择另一个明确直连的账号，这与同账号偷偷绕过绑定有不同的配置语义。

## 后果与验收

服务端必须统一覆盖生成、目录、健康检查和恢复四类执行点，单独存在代理管理页面或 transport 不算集成。
迁移需严格校验、回滚及修复后重试；代理不可用、凭据损坏或配置失配时相关账号失败关闭，管理员仍可修复。
已派发请求的旧连接只能关闭空闲池，不通过修改共享 transport 影响其他账号。

旧二进制可能不认识新增代理绑定表，所以本批 schema 本身不能提供技术降级屏障。降级必须恢复升级前完整
数据目录和匹配程序，禁止旧程序直接打开含新绑定的数据目录。后续升级工具应执行此要求，不能提前声称已有
自动回滚保护。完整接口、测试范围及暂未支持项见[出站代理契约](../outbound-proxy-contract.md)。
